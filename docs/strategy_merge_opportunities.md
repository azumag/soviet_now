# 併合経路を守る最終候補選択

## 対象と判断順序

盤面のAにNextNextのAを接触させる経路をNextのBで塞ぐ、大きい同型のDIRECT併合を非併合配置より後回しにする、近接する大きいA同士の空いた間へ小さいBを入れる、という3症状を対象にする。

`decide → runtime safety → finalize_decision → runtime safety` の後に、戦略の `merge_opportunity_alternatives` を呼ぶ。現在の手がDIRECT/NEAR、または盤面がすでに締切を超えている場合は変更しない。露出した同型への接触狙いも、別の非併合配置へ交換しない。

1. 次ピースがtype 8以上なら、解析器がDIRECTと判断する安全候補を優先する。
2. 非併合配置では、NextNextの最後の露出同型への経路と、type 8以上の近接同型ペアの空いた接触経路を比較する。少なくとも一つを改善し、もう一方も悪化させない候補だけを提案する。小型ペアの振動狙いはこの保護の対象外。
3. 形状は解析器の回転後の外接範囲を共用する。候補にcrossing/合体結果crossing/壁回転リスクがある場合や、予測上端の余裕が0.5未満の場合は提案しない。非併合への交換で予測上端を0.35超引き上げない。
4. runnerは順位順の最大8候補を既存の完全な安全判定へ通す。安全判定がxを変えた候補は拒否し、その移動先を無条件に採用しない。安全判定の緊急回避を許すreason文字列は持ち込まない。候補が通らない・入力不正・hook失敗時は元の安全判定後の手を保持する。

8候補の上限は、背の高い盤面で似た候補を大量に再検査して入力を遅延させないため。全ての安全な置き場所を探索する保証ではない。外接範囲による被覆/隙間判定も接触の近似であり、Unityの併合成立やプレイ改善は別途実戦で検証する。

## 履歴・互換性

`extract_decide_hash.py` は新hookとそこから呼ぶ関数を戦略hashへ含める。hookがない既存戦略のhashと挙動は維持する。反映時は戦略・runner・hash計算を一式で扱う。`decide()` だけを呼ぶ検証ではこの最終選択は評価できない。

旧戦略の係数群や壊れた旧ペア減点を単純に再有効化せず、保護対象の幾何計算・候補順位・実行可否を分けた最終段で補う。大きな旧評価軸の整理は別変更として比較する。

- 本番戦略の差し替え、自動改善の再開、実戦A/B、併合率/ソ連建国率の改善確認は実施していない。

### 固定入力での差分と時間

458手中5手（1.09%）を変更し、変更手の予測上端リスクは全て同等以下。次手の実併合結果はこの比較からは判定できない。Mac上の同一入力・解析済み盤面に対する判断処理は、baseline→候補でmedian 1.05→1.11ms、p95 5.09→5.19ms、最大9.33→18.49ms。新戦略hashは `0371aca3a0ab`。VM上の処理時間は未測定。

主担当が差分・後方互換・不正入力・reasonによる安全回避・現在の併合狙いの保持・戦略hashを自己レビューした。ユーザー指定によりサブエージェント/独立レビューは使用していない。
