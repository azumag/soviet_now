# ニュースのコーナー間重複判定

通常ニュース (`news`) と時事ニュース (`jiji`) は、選定時に両方の既読台帳を
読み取る。見出しの正規化キー・URL hashは両台帳の保持分を参照し、同一事件の
語集合はそれぞれの直近 `NEWS_EVENT_HISTORY_LIMIT` 件（既定60）を参照する。
片方の台帳が未作成でも、もう片方を照合する。

既存台帳の書き込み先・保持件数・スパム除外記録・ユーザー設定は変更しない。
履歴を移行・削除せず、追加のAI呼び出しやworkerを導入しない。
`NEWS_EVENT_DEDUP=0` は語集合による判定のみ無効化し、コーナー間の完全一致・
URL一致判定は維持する。自主探索の話題選定は従来の生成プロンプトによる回避で、
この修正は生成本文を意味解析して全ての反復を保証するものではない。

日本語の言い換えは、従来の内容語判定に加え、政府による電気料金支援について
「電気代支援の継続」「電気料金の補助金延長」を限定的に同一視する。
政府・首相・内閣、電気代・電気料金、支援・補助、明確な開始/延長/終了の
全条件が必要。明示された政府の国、反対/否定/見送り、両見出しに明示された
段階、金額、月、年、割合が異なる場合は
同一視せず、続報を候補に残す。一般的な日本語の意味類似性判定ではない。
独立した鮮度・話題・スパムフィルタは引き続き適用される。

検証は `python3 -m unittest -v tests.test_news_shared_history`。
実際の両shellフィルタを合成履歴で実行し、コーナー間の言い換え・正規化キー・
URL一致、初回起動、事件判定OFF、別事件と実質的続報を確認する。
実ニュースの放送内容は別途runtimeで確認し、合成テストと混同しない。
