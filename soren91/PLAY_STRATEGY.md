# メリケンAI: 認識・投下・戦略の検証契約

## 変更範囲

`strategy.mjs` は外部 import のない純粋な判定器を維持する。毎試合の戦略スナップショットは試合中に差し替えない。
`main.mjs`、配信基盤、モデル・課金設定、ランキング画面判定、コメント生成は変更しない。

## 画像認識から入力まで

- ピクセル走査を画像内の整数座標に制限し、解像度に合わせて走査間隔・UI余白を調整する。
- サンプリング幅を含めて半径を測り、小ピースの縮みを補正する。既に円形の近接ピースを国旗模様の断片として結合しない。
- 未検証の代表色で盤面のサイズ分類を上書きしない。不確かな断片も低信頼度の障害物として残し、合体を確定扱いしない。位置だけで実ピースを消す固定ゴースト座標は使わない。
- NEXT は3スロットの位置を維持し、不明は `null`。後続スロットを繰り上げず、架空の type 1 を補わない。
- 認識できた HOLD も2観測で確認する。`hold: null` は未検出/不明を含み、空とは断定しない。空HOLDの利用には明示的な `holdKnownEmpty: true` が必要で、現在の画像認識器はこのフラグを発行しない。
- おじゃま量は暗い背景を含む盤面内面積比。壁・細いUI線・認識済み円内部を除き、局所的な灰色領域の高さを `garbage.columns` に渡す。
- 初回の空盤面でも既存の壁検出で校正を試み、成功した座標を入力ループと共有する。暫定・fallback・別解像度の座標では投下しない。
- 現在ピースと盤面・おじゃまの安定を2観測で確認する。認識不明や動作中は既存ループの `DROP` 状態で再観測し、試合終了を表す `WAITING` に変換しない。実際のラウンド遷移は変更しない。
- 時系列状態はホットリロード外の `observation_guard.mjs` に校正オブジェクト別で保持し、画像や古い盤面を使い回さない。

## 戦略

15種類の既存半径表を使用し、固定1.20の着地バッファと線形の半径推定を廃止する。
円同士の最初の接触を計算し、別ピースに遮られた同種を合体候補としない。合体後は消費された相手を盤面から除き、上位ピースを配置して次の手を評価する。

安全・警戒・危険の順で候補を比較し、合体報酬が危険投下を正当化しない。高さ・混雑・凹凸・不確実性は減点し、局所的なおじゃまの上へ置く不利益も評価する。
最大49候補から上位6候補を残し、既知のNEXTを最大2手先まで各手貪欲に評価する。負の将来評価を0に丸めず、欠損したスロットで先読みを止める。HOLDとの比較には同じ探索と僅差の入替防止を使う。

これは限定的な幾何モデルであり、Unityの転がり・跳ね返り・複数物体の再配置・おじゃま消去を完全再現しない。`diagnostics` の値は推定であって実測スコアではない。

## 自動改善の採用前検証

`strategy_contract.mjs` を単発・集約の両方の既存採用経路から呼ぶ。NaN/Infinity、範囲外、入力改変、使用不可HOLD、欠損NEXTの繰り上げ、危険な中央投下の回帰を拒否する。同じ契約を改善プロンプトにも渡す。
この回帰検査は実戦優位性や任意の生成コードの安全性を証明するサンドボックスではない。モデル/権限/既存採用頻度は変更しない。

## 再現テスト

リポジトリルートで既存lockfileから依存を導入し、実行する。

```sh
npm ci --ignore-scripts --no-audit --no-fund
node --test tests/test_soren91_play.mjs
node --test tests/test_soren91_*.mjs
```

合成RGBA/PNG・盤面モデル・既存校正器による空盤面起動・校正失敗時の入力抑止・ホットリロードを検証する。乱数ケースは固定seedで再現可能。計測は80ピース/3スロット/HOLDを含むCPU時間であり、勝率ベンチマークではない。
既存ランキング判定コードと `calibration.mjs` 自体は変更しない。

## 実機採用条件（未実施）

本番用画像で NEXT の各スロットと実際の投下ピースの対応、国旗の型、半径、HOLD、局所おじゃまを目視ラベルと照合する。現行のNEXT代表色は仮定が残るため、合成画像での成功を実画像精度に換算しない。

旧版/新版を同程度の時間帯・対戦条件で比較し、順位の取得率と中央値、早期敗退、危険投下、認識保留の回数/継続時間を記録する。認識保留が続く場合は入力を盲目的に再開せず、画像と校正を修正する。
クリック後に実際の投下が受理されたかを確認する実機テストは別途必要。現行ループの「クリック送信=1ターン」計上は今回変更していない。

## docichからの配備

最新HEADのレビューとCI成功後に soviet_now main を確定し、それから docich の `games/soviet_now` gitlink をそのmainへ更新する。未マージの実験SHAを本番参照にしない。
配備は docich のowner-gated control plane のみを使い、VMのdriftを無視しない。旧SHA・対象ファイルを保存し、認識器・guard・戦略・契約・improveを同一コミットで扱う。試合境界でプレイヤーを更新して新しい戦略スナップショットを確認する。旧戦略実行中にnullable NEXTだけをホット適用しない。
配信・共通音声・通知基盤は再起動しない。対象ファイルのSHA-256、実行中プレイヤーの新PID/戦略hash、共通配信PIDの維持を別々に検証する。異常時はowner経路で旧一式へ戻す。

実戦順位、VM一致、OBS/操作入力の実測がない段階は本番改善完了とは扱わない。
